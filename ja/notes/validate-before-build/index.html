プロダクト思考 / 実験方法

開発する前に検証する：低コスト実験の4つの問い

技術的に実現できることと、ユーザーが必要としていることは別です。「面白い」という反応も、継続利用や支払いの意思を意味しません。

1. 課題は本当に存在し、頻繁に起きるか？

ユーザーが表計算、コピー＆ペースト、有料ツール、人手で解決しているかを観察します。口頭の関心だけでなく、実際の行動を確認しましょう。

2. どの具体的な痛点を解決するか？

大きな目標を、入力・出力・失敗条件が明確な検証タスクに分解します。

3. 使えると判断する指標は？

成功率、修正時間、情報精度、再利用率、転換率、単位コストなど、プロジェクトに合った指標を事前に決めます。

4. いつ続け、いつ止めるか？

サンプル拡大、修正して再テスト、投資停止の判断基準を実験前に決めます。停止は失敗ではなく、根拠のない追加投資を避ける方法です。
